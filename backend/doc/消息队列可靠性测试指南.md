# 消息队列可靠性测试指南

## 概述

本指南提供了详细的测试步骤，用于验证 BI 项目中消息队列的可靠性改进措施是否生效。

## 前置条件

1. RabbitMQ 已启动（端口 5672 和 15672）
2. MySQL 已启动
3. Redis 已启动
4. 后端服务已编译并可以启动

## 测试清单

### ✅ 测试1：生产者确认机制

**目标**：验证消息发送成功时收到确认

**步骤**：
1. 启动后端服务
2. 上传一个 Excel 文件生成图表
3. 查看日志

**预期日志**：
```
[BiMessageProducer] 检测到事务环境，注册事务后钩子: chartId=1
[BiMessageProducer] 事务提交成功，发送MQ消息: chartId=1
[BiMessageProducer] MQ消息发送成功: chartId=1, exchange=bi_exchange, routingKey=bi_vip_routing_key
[RabbitMqProducerConfig] 消息发送成功到达Exchange: correlationId=1
```

**判断标准**：
- ✅ 看到 "消息发送成功到达Exchange"
- ✅ 没有报错日志

---

### ✅ 测试2：消息持久化

**目标**：验证 RabbitMQ 重启后消息不丢失

**步骤**：
1. 启动后端服务
2. 生成一个图表请求
3. **在消息尚未被消费时**，立即重启 RabbitMQ
   ```bash
   docker restart rabbitmq
   ```
4. 等待 RabbitMQ 重启完成（约10秒）
5. 查看队列中是否还有消息
   ```bash
   docker exec rabbitmq rabbitmqctl list_queues name messages
   ```

**预期结果**：
```
bi_vip_queue    1
bi_common_queue 0
bi_dl_queue     0
```

**判断标准**：
- ✅ RabbitMQ 重启后，队列仍然存在
- ✅ 消息仍然在队列中（messages > 0）
- ✅ 后端服务重启后，消息被正常消费

---

## 常见问题

### Q1: 消息发送成功但未收到确认回调？

**可能原因**：
1. RabbitMqProducerConfig 未正确初始化
2. CorrelationData 未设置

**解决方法**：
1. 检查 @PostConstruct 方法是否被调用
2. 检查 CorrelationData 是否传递给 convertAndSend

---

### Q2: 消息重启后丢失？

**可能原因**：
1. Exchange 或 Queue 未持久化
2. Message 未设置 PERSISTENT

**解决方法**：
1. 检查 RabbitMqConfig 中的 durable=true
2. 检查 BiMessageProducer 中的 MessageDeliveryMode.PERSISTENT

---

### Q3: 死信队列没有收到消息？

**可能原因**：
1. 死信交换机或路由键配置错误
2. 业务队列未绑定死信交换机

**解决方法**：
1. 检查 RabbitMqConfig 中的死信配置
2. 检查队列参数 x-dead-letter-exchange 和 x-dead-letter-routing-key
